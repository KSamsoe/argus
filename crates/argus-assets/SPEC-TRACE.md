# argus-assets: spec trace

Every statement in the design document (v0.3) that constrains the asset importer as phase 1 item 4 scopes it (§14 "Assets", §4 `.argus/` is a cache, §8 events, §18 phase 1), with where it lives and the test that pins it. Statuses as in the other traces: **Done**, **Partial**, **Deferred**.

## §14 Assets

| Spec | Status | Where | Test |

| A material (§13, item 11). | Done | `<name>.wgsl`, with a sidecar of typed parameters (`type = "material"`, or `shader`, `params`, or `blend`), or a sidecar naming a library material's shader to vary its defaults. `argus-material` reads it and checks the composed shader with naga at import, so a compile error fails the import with the `.wgsl`'s own line. | A particle effect (§13, item 10). | Done | A sidecar with `type = "emitter"` (or `rate`, `burst`, or `lifetime`) is an asset of kind `emitter`: `effect.rs` reads the shape, rate, burst, duration, max, lifetime and speed ranges, direction, spread, gravity, drag, space, z, and the curves over life (velocity, size, rotation, colour) as control-point lists, and checks the ranges, the colours, and that each curve's t runs from 0 to 1 and never back. | Generated art drops into the same tree and gets the same treatment. | Done | There is no other path: any PNG under `assets/` is imported the same way. | |

## Phase 5, item 4: Aseprite files

| Spec | Status | Where | Test |
|---|---|---|---|
| (§14) An Aseprite file imports natively: a sprite's source in place of a PNG. | Done | `aseprite.rs` reads the file as Aseprite's `ase-file-specs.md` describes it: the header, frames with their durations, layers (visible, image, group, or tilemap, child level, blend, opacity, name), cels (raw, linked, and zlib-compressed), palettes old and new, tags, slices (keys, 9-patch centre, pivot), and user data; a colour profile is ignored without a warning, and a chunk of a type the spec does not list is skipped by its size with one. RGBA, grayscale, and indexed (the transparent index clear except on the background layer). Each frame is drawn from the visible layers with Aseprite's own normal blending: layer and cel opacity, a group's visibility, and a group's opacity over its layers drawn together. Other blend modes draw as normal with a warning naming the layer and the mode; a tilemap layer is skipped with a warning; a reference layer is not drawn. The frames are laid out on one sheet in the cache, each the canvas's size, in the column count that makes the smallest power-of-two texture (Hollow's eight 8 x 13 hero frames fit 32 x 32), and frames of the same pixels (a linked cel) share one place. `name.png` beside `name.aseprite` is AMBIGUOUS, as other clashes are; a normal map beside one is refused with why. | `aseprite::rgba_grayscale_and_indexed_files_draw_as_aseprite_draws_them`, `aseprite::raw_compressed_and_linked_cels_land_at_their_offsets`, `aseprite::layers_and_groups_draw_with_their_visibility_and_opacity`, `aseprite::a_png_and_an_aseprite_of_one_name_are_ambiguous_and_ase_is_one_too` |
| (§13) Aseprite tags import directly as clips. | Done | A tag is the clip of its name: frames `from` to `to`, played by each frame's duration (no fps; the animator already plays per-frame durations), in its direction (a ping-pong reverse is a ping-pong over the frames listed `to` down to `from`). Repeat 0, which Aseprite plays forever, loops; repeat 1 plays once (a ping-pong one way); repeat n is the whole sequence listed n times, played once. A tag past the last frame, and a second tag of one name, are dropped with a warning. | `aseprite::tags_become_clips_in_every_direction_with_the_frames_durations` |
| Slices: pivots and hitboxes. | Done | The slice named `pivot` (or else the first with a pivot) sets each frame's pivot where it has a key: its pivot point, or its middle; a point is a pixel's corner, so (8, 16) on a 16 x 16 canvas is `[0.5, 0.0]`. Two slices with pivots and none named `pivot` is a warning. Every other slice is the frame property `slice.<name>` = `"x y w h"` (pixels from the frame's top left, y down, a frame rect's shape) in the frames it has a key in, and a 9-patch's centre `slice.<name>.center`, relative to the slice. A cel's user data text is its frame's `data` property and its user properties are frame properties, from the layers drawn. | `aseprite::slices_set_pivots_and_hitboxes_and_cel_user_data_is_frame_properties` |
| The file's structure exposed, for a sidecar written without opening Aseprite. | Done | `SpriteAsset::aseprite` (`aseprite::Info`), shown by `asset.get` under `aseprite` (and in the manifest): the canvas and depth, every layer (name, path through its groups, kind, visible, opacity, blend, used), tag (name, from, to, direction, repeat), and slice (name, keys with bounds, centre, pivot). `aseprite::describe(bytes)` reads it without drawing. | `aseprite::layers_and_groups_draw_with_their_visibility_and_opacity`, `aseprite::tags_become_clips_in_every_direction_with_the_frames_durations` |
| The sidecar over an Aseprite file. | Done | `layers = ["body", "fx/sparks"]` picks the layers drawn, by name or path (a picked layer is drawn even if hidden; a picked group draws its visible layers); a name the file lacks is a warning, and naming none it has is refused with the line. `pivot`, `duration_ms`, and `pixels_per_unit` replace the file's for every frame; `[[frames]] index = n` changes one frame; `[clips.<tag>]` changes only what it writes of the tag's clip (`fps`, `loop`, `frames`; `direction` plays the tag's frames from..to that way), so it may leave out its frames, and a clip with no frames and no tag of its name is refused; a clip of another name is a clip of its own. `grid`, a frame's `rect`, and a shape's keys are warned of and ignored. Beside a PNG, `layers` is an unknown key and a clip still needs its frames, as before. | `aseprite::the_sidecar_changes_only_what_it_writes_and_an_empty_frame_is_reported` |
| Every import reported with warnings; the tree watched. | Done | As any sprite: "frame 2 is empty" (at the file), the warnings above, and the file and its sidecar re-imported when either changes; a removed file removes the asset and its cached texture. | `aseprite::a_changed_file_imports_again_and_a_removed_one_goes` |
| A file that is not one, or is damaged, is refused with why. | Done | A failed import (BAD_SOURCE) at the file, saying what is wrong and where ("its header's magic number is 0x6920, not Aseprite's 0xA5E0"; a file cut short names the frame, its byte, and how much it lacks), never a panic: every read is bounds-checked, a canvas or cel is at most 4096 x 4096, all frames 64 Mi pixels, 4,096 layers 64 groups deep, and a compressed cel inflates to its size at most. | `aseprite::a_malformed_file_is_refused_with_why_and_never_panics` (every truncation, every byte flipped) |
| (§15) A release pack carries an Aseprite sprite as any sprite. | Done | Its source is the `.aseprite` file, so `packed_sprites` leaves it (and its sidecar) out of the pack and the cached sheet goes on a page like any other; the release build never reads the file. | argus-player `release_aseprite::hollows_hero_from_an_aseprite_file_looks_as_the_png_from_its_folder_and_its_pack` (Hollow's hero as an Aseprite file draws the PNG hero's pixels from the folder and from the pack, standing and running) |
| Checked against Aseprite's own output. | Done | The 13 files Aseprite wrote on this laptop (one layer, one frame each) read without a warning; the 7 with an Aseprite PNG export beside them match it pixel for pixel, except two pixels in one whose `.aseprite` was saved a minute and a half after its export. | (by hand, 2026-10-08) |

## Phase 5, item 4: Tiled files

| Spec | Status | Where | Test |
|---|---|---|---|
| (§14) A Tiled tileset imports natively, as a sprite asset. | Done | `tiled.rs`: a `.tsx` (or `.tsj`, Tiled's JSON) is a sprite named by its path under `assets/` without the extension. Its image (a PNG, relative to the file, anywhere under `assets/`) is cut into tiles by `tilewidth`, `tileheight`, `margin`, `spacing`, `columns`, and `tilecount`, in Tiled's id order, so tile `n` of a map is frame `n - 1`, which is Tiled's id `n - 1`. Each tile's custom properties (bool, int, float, string, color, file, object) are its frame's properties as text, so `solid`, `one_way`, and `slope` collide as they do from a sidecar; a class property is warned of and left out. A tile's animation is a clip named by the tile's class, or `tile<id>`: even steps as an fps, uneven ones as each frame's duration. `pixels_per_unit` is the tile's width (one tile, one world unit), or the tileset's property of that name. A sidecar beside it (`<name>.toml`) adds `[autotile.<terrain>]` rules, frame overrides by index, clips, and `pixels_per_unit`; its `grid`, frame rects, and shape are ignored with a warning, since the tileset says where its tiles are. `<name>.png` beside `<name>.tsx` is its image when the tileset says so, and ambiguous when it does not. An image collection (an image per tile) is refused with why. | `tiled::a_tileset_imports_as_a_sprite_with_its_tiles_properties_and_animations` |
| (§14) A Tiled map imports natively, its structure exposed. | Done | A `.tmx` (or `.tmj`) under `assets/` is an asset of kind `tilemap` (`Asset::Map`). `asset.get` shows its size, tile size, and properties; its tilesets (name, firstgid, tile count, the sprite asset, embedded or a file); every Tiled layer, groups flattened (kind `tiles`, `objects`, or `image`, visible, its tilesets, the engine layers it became); the engine layers (name, kind, the Tiled layer it came from, tileset, collision, z, visible, tile count, properties); and its object layers' objects. `asset.list kind=tilemap` lists them, the frames and clips columns being the engine layers. An embedded tileset is a sprite asset of its own, named `<map path>/<tileset name>` (`maps/level1.tmx/terrain`, a name no file can have), imported, watched, and removed with its map (`Importer::expand_tiled` adds it to the scan as an asset of its own). `read_map` is the reading argus-tiles makes the engine's map from, so the import and the game see one map. | `tiled::a_map_imports_with_its_layers_tilesets_and_objects_exposed`, `tiled::tmj_and_tsj_read_as_the_same_map`, `tiled::the_watcher_reimports_a_changed_tileset_and_a_maps_embedded_tilesets_follow_the_map` |
| Layer data as Tiled writes it. | Done | CSV, base64 uncompressed, zlib, and gzip, in finite maps and infinite ones (chunks), and the old XML `<tile gid>` form; base64 is decoded by hand, the compression by `flate2`, the XML by `quick-xml`. zstd is refused with the hint "Save it with zlib, gzip, or CSV". | `tiled::tests::layer_data_decodes_from_uncompressed_base64_and_xml_tiles`, `tiled::an_infinite_map_is_the_bounds_of_its_chunks` |
| Object layers: data, not entities. | Done | Each object's id, name, class (Tiled's `type` before 1.9), shape (rect, ellipse, point, polygon, polyline, tile, text), top-left corner (a tile object's from its bottom-left) and size in world units from the map's top-left corner, y up as the world's (a `Tilemap` at (x, y) has the object's corner at (x + pos.x, y + pos.y)), rotation, a polygon's points, a tile object's tileset and tile, visibility, and properties, with its layer's group offset. The engine makes no entity of them: a game reads them as data. | `tiled::a_map_imports_with_its_layers_tilesets_and_objects_exposed`, `tiled::an_infinite_map_is_the_bounds_of_its_chunks` |
| Every import reported with warnings. | Done | Each at the file's line (the file, in JSON): flipped or rotated tiles (once a layer), opacity, tint, parallax, image layers, objects from templates, a tile offset, a tileset grid not orthogonal, Tiled's terrain sets, tiles with collision shapes and no collision property, tiles of no listed tileset or past their tileset's end, tiles an offset moves off the map, an offset not in whole tiles, a sheet holding fewer tiles than the tileset says, empty tiles (one line), animations made clips, two layers of one name (the second numbered), a tileset with tiles of another size than the map's, an external tileset outside `assets/` or unreadable, and an embedded tileset in a map outside `assets/`. | `tiled::a_map_imports_with_its_layers_tilesets_and_objects_exposed`, `tiled::a_tileset_imports_as_a_sprite_with_its_tiles_properties_and_animations` |
| A file that is not one, or that the engine cannot read, is refused with why. | Done | A failed import at the file (and its line where there is one), never a panic, the rest imported: malformed XML or JSON, a map that is not orthogonal ("the engine's maps are a square grid"), tiles that are not square, a layer whose data is not its size, zstd, an image collection, an image outside `assets/` or not a PNG. Sizes and offsets a hand edit makes absurd are refused, not overflowed. | `tiled::what_the_engine_cannot_read_is_refused_with_why_and_the_rest_imports`, `tiled::a_damaged_map_or_tileset_is_an_error_never_a_panic` (the fixture map and tileset, XML and JSON, cut short at every byte and every byte changed) |
| (§15) A release pack carries them. | Done | A tileset's sprite, embedded ones too, goes through the catalog and its pages like any sprite, its image left out of the pack; the `.tsx` and the `.tmx` ship as files (the map is read at start; the tileset file only for its name and tile count). | argus-player `release_tiled::a_game_on_a_tmx_ships_and_plays_from_its_packs_as_from_its_folder` |

## Known limitations, stated so they are decisions

- The watcher polls file metadata twice a second rather than using OS notifications. It is deterministic, has no dependency, and costs one metadata read per file.
- A daemon start re-imports every asset: the cache is written for the renderer, but the manifest is not read back to skip work. Fine at example scale; reading the manifest is the change when a project's asset count makes the cold open slow.
- PNG and WAV only, and TrueType and OpenType fonts (not collections). Other image and audio formats, and the native Aseprite and Tiled readers, come later. (Aseprite and Tiled files are read since phase 5 item 4.)
- Of Tiled's files the engine does not read: maps that are not orthogonal or whose tiles are not square, zstd-compressed layers, image-collection tilesets, a tile's collision shapes (a tile collides by its `solid`, `one_way`, or `slope` property), Tiled's terrain sets (auto-tiling is the sidecar's `[autotile]`), image layers, object templates' own fields, and a layer's opacity, tint, and parallax; each is a warning or a refusal with why, never silent. Flipped and rotated tiles draw unflipped. A tile animation is a clip a Sprite plays; a map layer draws its tiles still. An embedded tileset is a sprite only when its map is under `assets/`.
- An Aseprite file's frames are each the canvas's size on the sheet, not trimmed to their pixels: a trimmed frame would need a pivot outside it, which the frame model clamps. Its blend modes other than normal draw as normal; its tilemap layers are skipped; a z-index orders a cel among its siblings in its group only; a normal map cannot go with it, since the importer lays its frames out.
- A font imports in about 0.3 s in a debug build (Liberation Sans, 208 glyphs, a 472 x 388 atlas); it is not written to the cache, so a daemon start bakes it again.
- Placeholder shapes are drawn with hard edges at their pixel size; the renderer's nearest-neighbour magnification keeps them crisp.
- Every `.json` under `assets/` is read as a Spine skeleton (phase 5 item 8), so another JSON file there is refused as not one: a game keeps its data elsewhere (`defs/`).
- Of Spine's exports the engine reads the JSON with its images unpacked; a packed `.atlas` and the binary `.skel` are not read.
