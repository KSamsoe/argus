# Argus 0.2.0

0.2.0 is online multiplayer. Two to four players, each at their own machine, play one game together, on Windows, Linux, a Mac, or in a browser, in any mix. Each machine runs the same game and sends only what its player does, through a relay every player connects out to, so it works behind home routers. A new example, Duel, shows it: two fighters in one arena, first to three, played on one keyboard or online.

It is 0.2.0, not 0.1.3, because making every machine compute the same world changed some of the engine's arithmetic. A replay, a report, or a golden recorded on 0.1.x may not end on the same world now ([below](#breaking-changes-from-012)). Games themselves need no change.

## New: the same run on every machine

- **One math library.** Every sine, cosine, exponential, and power the engine computes for the world (tweens' easing, the transform hierarchy's rotations, the camera's follow, zoom, and shake, skeletons, physics) comes from one library that gives the same bits everywhere, where each platform's own rounds a few results in a hundred differently. So does Luau's: a script's `math` functions, `^`, and `vector.angle`. A Rust plugin has the same functions in its SDK, `argus_plugin::math`.
- **Checked before each release.** CI's new det step plays every example's long runs and all its scenarios on Windows and Linux, and the runs again in Chrome, and fails on one differing bit. For 0.2.0 all of them matched, puppet's skeletons included, which differed on every platform before.

## New: multiplayer

- **Matches with prediction and rollback.** A tick runs at once with what is known; a player whose actions have not arrived is guessed to be doing what they were doing, and when the guess was wrong the game goes back and runs the ticks again before drawing. Each player's input is delayed a few ticks, so a quick link guesses nothing: 2, or what the game chooses in `argus.toml` (`[net] delay`), however the match is hosted. A turn-based game plays in lockstep. Every second the players compare their worlds, and if two ever differ the match stops and says which fields. Either player's report replays the whole match. ([Multiplayer](https://github.com/KSamsoe/argus/blob/v0.2.0/docs/manual/multiplayer.md))
- **The relay.** `argus relay` is in the install: rooms with five-letter codes, passing each player's messages to the others and keeping nothing, with limits that make it safe to leave running. `lag=` and `jitter=` make a link slow on purpose. It listens on this machine or a tailnet unless told `public`; the Releasing chapter says what a public relay exposes.
- **Hosting and joining.** A game's own menu calls `q:net_host(players, scene)` and `q:net_join(code)`, and `q:net()` says where it is: a room and its code, then the match. Once every slot is taken, every player opens the scene afresh from the host's seed. The desktop game takes `--relay`, `--host`, and `--join <code>`; the web page `?relay=`, `?room=`, and `?host=`. The daemon plays one side with `net.host` and `net.join`, so an agent can play against a person.
- **Testing a match.** A scenario's `t:net { players = 2, latency = 60, jitter = 30, loss = 0.05 }` plays the rest of the run as every player of a match over a network that bad; `t.input:slot(n)` is each player's input, and the run fails the moment two worlds differ, naming the fields.
- **Two players on one keyboard.** `[slots.2.keys]` gives a slot keys of its own for an action, and prompts show them.

## New: Duel

`examples/duel`: two fighters, each with a move, a dash that cannot be hit, and a swing; first to three wins. A title menu plays two on this machine, hosts online, or joins by a code. Player 1 has WASD, F, and Space; player 2 the arrows, period, and slash; pads and touch too. Online its input delay is 3, and a swing's slash outlives its hitbox, fading, so the other player's swing shows even when a slow link brings it late. It is among the example games to download.

## Fixed

- **The software rasteriser draws sprites as sharp as a GPU does.** `obs.frame` with `software = true`, and picture goldens, blurred zoomed-in sprites and could show a thin tinted strip along a frame's edge; they now filter as the GPU does.

## Breaking changes from 0.1.2

- **Some recordings made on 0.1.x will not end on the same world.** The engine's math (and Luau's) now gives the same bits on every platform, which on Windows and Linux differs in the last bit from 0.1.x for a few results in a hundred. A game that eases tweens with sine or power curves, a camera that follows, zooms, or shakes, a skeleton, or a script calling `math.sin`, `math.exp`, `^`, and the like may end a replay, a report, or a scenario elsewhere. Record goldens again (`argus test --update`) where a picture or a state golden changed; the examples' are recorded again. A picture golden of zoomed-in sprites may change too, now that the software rasteriser draws them sharp.
- **A Rust plugin is built against plugin ABI 2.** The daemon rebuilds a project's plugins on its own; a release built on 0.1.x is built again.
- **In a match, `input.inject`, `input.message`, and a page's `player.message` are refused**, since every input there must come through the match.

## Install

`install.ps1` (Windows) or `install.sh` (Linux and macOS), from the archive or with a GitHub token from this release; see [docs/install.md](https://github.com/KSamsoe/argus/blob/v0.2.0/docs/install.md). An install from 0.1.x updates with `argus self-update`. The macOS build is cross-built on Linux and universal (Apple Silicon and Intel); [docs/mac-testing.md](https://github.com/KSamsoe/argus/blob/v0.2.0/docs/mac-testing.md) is the packet for checking it on a Mac, with `mac-expected.json`. To play the example games with nothing installed, there's `example-games-0.2.0` for Windows, Linux, or macOS; each archive's `README.txt` has the controls.
